# 문제 해결과 알려진 제한 사항

[English](../troubleshooting.md) · 한국어

재생 중 **Ctrl+K**를 누르면 AI 자막의 상태(얼마나 앞서 있는지, 입력 소스, 오류)를 볼 수 있습니다.
대부분의 메시지는 어느 **Ctrl+N** 항목을 열어야 하는지도 알려 줍니다.

## 자주 겪는 문제

### 설치 파일이나 프로그램이 Windows에서 경고 대상이 됩니다

릴리스 파일은 코드 서명과 타임스탬프가 적용되어 있습니다(게시자 *Nanum Space Co,. Ltd*). 그러나
SmartScreen은 파일이 얼마나 자주 내려받아졌는지도 보기 때문에 새 릴리스에서는 여전히 "Windows가
PC를 보호했습니다"가 표시될 수 있습니다. 파일의 SHA-256을 같은 릴리스 페이지의
`SHA256SUMS-<version>.txt`와 비교한 뒤(`Get-FileHash <file> -Algorithm SHA256`) **추가 정보 → 실행**을
선택하세요. 패키지에 포함된 서드파티 DLL은 각자의 서명 상태를 유지합니다.

### AI 자막이 나타나지 않습니다

다음 순서로 확인하세요.

1. **번역 서버.** Ollama가 실행 중입니까(`ollama serve`)? **Ctrl+N → 번역 모델**에 서버의 모델 목록이
   표시됩니다. 목록을 가져올 수 없다면 서버에 연결할 수 없거나 주소가 잘못된 것입니다. 서버가 꺼져
   있으면 모든 번역이 `transport error`로 실패하고, 프리롤은 제한 시간(90초)까지 기다리며, 번역되지
   않은 줄은 원문으로 표시되고 서버에 연결할 수 없다는 상태 칩이 나타납니다. 영상을 열기 전에 서버를
   시작하세요.
2. **음성 모델.** 음성 인식에는 해당 언어의 Whisper 모델과 VAD 파일이 필요합니다(**Ctrl+N → AI 구성
   요소 관리**). 없으면 재생은 정상적으로 시작되고 무엇이 없는지 알려 줍니다. 다운로드가 끝나면 다음에
   여는 파일부터 적용됩니다.
3. **목표 언어 자막이 이미 있습니다.** 이 경우 플레이어는 그 자막을 보여 주고 AI 작업은 의도적으로
   건너뜁니다. 자막 목록에서 `[AI]` 항목을 선택하면 시작합니다.
4. **`[원본 자막]` 또는 `[파일]` 자막을 선택했습니다.** AI 항목을 고를 때까지 AI 작업이 일시 중지됩니다.
5. **입력 소스.** Ctrl+N → 입력 소스: *자동*은 오디오 언어의 텍스트 자막을 우선합니다. 이미지 자막(PGS)은
   OCR을 통해서만 사용됩니다.

### 자막이 늦게 도착합니다

자막은 선읽기가 허용하는 만큼만 일찍 도착합니다. 기본 선읽기는 1초이므로 자막이 대사보다 늦게
도착합니다. `--demuxer-readahead-secs`(와 함께 `--demuxer-max-bytes`)를 올리세요.
[참조](reference.md#선읽기)를 확인하세요. 48 Mbit/s 먹스에서 120초는 약 720 MB입니다. 탐색 후 아직
처리되지 않은 구간은 자막이 늦게 나타날 수 있으며, 처리가 따라잡으면 표시됩니다.

### 모델이 너무 느리거나 번역이 시간 초과됩니다

기본 이름 `gemma4:latest`는 12.8 GB입니다. 8 GB GPU에서는 일부만 GPU에서 실행되며, 음성 인식과
렌더러가 함께 동작하면 시간 초과가 날 수 있습니다. **Ctrl+N → 번역 모델**에서 더 작은 로컬 모델이나
Ollama 클라우드 모델을 선택하세요. 모델의 품질은 고유명사에서 가장 중요합니다. 작은 로컬 모델은 이름과
감탄사를 번역하지 않고 남기거나 용어집 항목을 지어낼 수 있으므로 **용어집** 목록을 확인하세요.

### CUDA가 사용되지 않습니다

- CUDA 엔진에는 compute capability 8.6 이상의 NVIDIA GPU, 최신 드라이버, **CUDA 13** cuBLAS가
  필요합니다. CUDA 12만으로는 부족합니다. CUDA 13 Toolkit을 설치하거나 AI 구성 요소 관리에서 cuBLAS를
  내려받으세요.
- 드라이버를 찾을 수 없다는 메시지가 나오면 NVIDIA 드라이버를 설치하세요.
- *CUDA 필수* 모드에서 CUDA가 없거나 호환되지 않으면 이를 알리고 AI 자막 없이 재생을 계속합니다.
  *자동* 또는 *CPU만*으로 바꾸세요.
- 모드 변경과 다운로드는 다음에 여는 파일부터 적용됩니다.
- GPU를 쓸 수 있는데 CPU가 동작하면 재생 바 위의 태그에 `CPU ⚠`가 표시됩니다.

### 디스크 자막의 OCR 품질이 낮습니다

영어 이미지 자막을 한국어 인식기만으로 읽으면 보정 후에도 일부 오인식이 남습니다(예: `cold` → `00년`).
영어 OCR 언어 팩(**Ctrl+N → 영어 OCR 언어 팩 설치 (관리자 권한)**)을 설치하세요. 관리자 권한이
필요합니다. 일본어 트랙에는 일본어 팩이 필요합니다. 사이트에서 내려받은 자막은 컷과 편집이 사용자의
디스크와 다를 수 있어 자동 시간 맞춤의 신뢰도가 낮다고 보고될 수 있습니다. ±0.1초, ±1초 항목으로
직접 조정하세요.

### YouTube

- YouTube 도구(`yt-dlp`, Deno)는 선택 다운로드입니다: **Ctrl+N → YouTube**.
- YouTube가 로봇이 아닌지 확인을 요구하거나, 연령 제한·멤버십 전용·비공개 영상에 로그인을 요구할 수
  있습니다. YouTube 창에서 로그인한 뒤 다시 시도하세요.
- 비공식 도구로 계정을 사용하면 YouTube가 확인 절차를 추가하거나 계정을 제한할 수 있습니다.

### 웹페이지 영상이 재생되지 않습니다

DRM으로 보호된 영상, 재생 가능한 미디어나 매니페스트 주소를 로드하지 않는 페이지, 브라우저 밖의 재생을
차단하는 서버는 지원하지 않습니다. 주소가 만료되었다면 창에서 페이지를 새로 고치고 **NanumPlayer에서
재생**을 다시 누르세요. 브라우저 창이 열리지 않으면 WebView2 런타임이 없는 것이므로 Microsoft에서
설치한 뒤 다시 시도하세요.

### 디스크

- 암호화된 디스크에는 [선택 디스크 구성 요소](disc-components.md)가 필요합니다. 없으면 NanumPlayer가
  이를 알리고 설치를 제안합니다.
- 키가 필요한 Blu-ray는 공개 키 데이터베이스에 해당 항목이 없거나, BD+ 가상 머신 데이터를 쓸 수 없거나,
  AACS 버전 또는 드라이브 인증이 지원되지 않으면 여전히 실패할 수 있습니다. 이러한 실패는 숨기지 않고
  보고합니다. 모든 BD+ 또는 UHD 디스크에서 다른 도구와 동등한 지원을 한다는 주장은 하지 않습니다.
- 광 디스크에서는 전체 번역과 OCR이 두 번째 위치에서 읽기 때문에 서로, 그리고 재생을 느리게 합니다.
  이런 작업에는 로컬 파일을 사용하세요.

## 디스크 읽기와 탐색 진단

일반 재생 로그는 저장되지 않습니다. 명시적인 `--log-file`은 mpv의 표준 로그 정책을 따르며 주소와 파일
이름이 들어 있을 수 있으므로 비공개 시청에는 사용하지 마세요.

상세 디스크 로그는 **Ctrl+N → 진단 로그(디스크 읽기 상세)**, IPC 명령
`nanum-diagnostics on|off|toggle`, 또는 시작 시 환경 변수 `NANUMPLAYER_DIAGNOSTICS=1`로 켭니다.
로그는 `%APPDATA%\NanumPlayer\diagnostics\disc-<date>-<time>-<pid>.log`에 저장되며 파일당 최대
8 MiB, 최근 8개만 유지합니다.

로그에는 탐색 요청, 실제 도착 위치와 첫 데이터 도착, 읽기 오프셋·길이·소요 시간, 실패한 Windows
`ReadFile`의 오류 코드, 드라이브의 모델·펌웨어·연결 유형이 기록됩니다. 실패 후에는 관련 Windows
저장소 이벤트를 수집합니다. 키, 미디어 내용, 드라이브 일련번호는 기록하지 않습니다. 파일 읽기는
성공했지만 복호화가 실패한 경우와 실제 운영체제 읽기 실패를 구분합니다. 이 파일 I/O 계층에서는 SCSI
센스 데이터를 얻을 수 없으므로 이에 대한 오류 코드를 지어내지 않습니다.

## 알려진 제한 사항

- 검증한 디스크에서 AI를 끈 상태에서도 디스크 중반 이후 Windows CRC 읽기 오류와 `cdrom` 이벤트 7이
  관찰되었습니다. 이는 AI 준비 상태와 무관한 실제 I/O 지연입니다. 디스크, 드라이브, 연결 경로 중 단일
  원인은 분리하지 못했으며 복호화 실패도 발생했습니다.
- 재생 중에 **원어 음성으로도 자막 만들기**를 켜면 이미 선읽기한 구간(약 2분)은 건너뜁니다. 건너뛴
  구간은 그 위치로 다시 탐색할 때 분석됩니다.
- 다국어 `small` Whisper 모델은 일본어를 잘 인식하지 못합니다. 선택 사항인 large-v3-turbo 모델은 크게
  개선되지만 GPU 메모리를 더 쓰고 8 GB GPU에서는 로컬 번역 모델을 느리게 할 수 있습니다.
- 프리롤은 파일을 처음 열 때만 처리됩니다(기본 30초). 타임라인이나 방향키 탐색은 기다리지 않고 기존
  재생/일시정지 상태를 유지합니다. 아직 처리되지 않은 구간의 자막은 늦게 도착할 수 있습니다.
- 긴 발화(최대 15초)는 문장 끝에서 나누고 시간은 글자 수에 비례해 나눕니다.
- 종료 시 `0xC0000005` 충돌이 150초 실디스크 측정에서 한 번 관찰되었으나 이후 반복 검증에서는
  재현되지 않았습니다. 원인은 확인되지 않았습니다. 개인정보 보호를 위해 충돌 덤프는 기본적으로
  꺼져 있습니다. 진단이 필요할 때만 `NANUMPLAYER_CRASH_DUMP_DIR`을 폴더로 지정하고, 덤프에는 프로세스
  메모리가 들어 있으므로 민감한 파일로 취급하세요.
- **Ctrl+N** 메뉴에 없는 설정(모델 경로와 그 밖의 엔진 옵션)은 `mpv.conf`에 둡니다. 번역 모델, 서버,
  번역 목표 언어는 다음에 여는 파일부터 적용되며, 말투, 원어 음성 자막, 용어집은 즉시 적용됩니다.
- RTX 업스케일 상태의 "요청됨"은 드라이버가 영상을 처리하고 있다는 증거가 아닙니다.
- Windows 전용(x64)입니다. 다른 플랫폼은 빌드하지 않습니다.

## 도움 받기

여기에서 다루지 않은 문제는 [이슈를 열고](https://github.com/kimmingul/NanumPlayer/issues/new/choose)
버전(시작 화면과 **Ctrl+K**에 표시됨), Windows 버전, GPU, 번역 모델, **Ctrl+K**에 표시된 내용을
함께 적어 주세요. 비공개로 유지하려는 주소가 들어 있는 로그는 첨부하지 마세요.

## 보안 문제와 개인정보 문의

보안 문제는 공개 이슈로 올리지 마세요. [비공개 취약점 신고](https://github.com/kimmingul/NanumPlayer/security/advisories/new)를
이용하거나 [mgkim@nanumspace.com](mailto:mgkim@nanumspace.com)로 제목을 "NanumPlayer security"로 하여 메일을 보내 주세요. [SECURITY.md](../../SECURITY.md)를 참고하세요.
